# 1. What Is Python?

## 1.1 Definition

**Python is a high-level, general-purpose, dynamically typed programming language with a strong emphasis on readability, developer productivity, and a large standard library and ecosystem.**

Python supports several programming styles:

* Procedural programming
* Object-oriented programming
* Functional programming
* Imperative programming
* Event-driven programming
* Concurrent/asynchronous programming
* Metaprogramming

Python source code is generally executed through a Python implementation such as **CPython**, rather than directly by the CPU.

A simplified view is:

```text
Python Source Code
       │
       ▼
   Python Parser
       │
       ▼
   AST / Compilation
       │
       ▼
   Python Bytecode
       │
       ▼
Python Runtime / Interpreter
       │
       ▼
Operating System
       │
       ▼
CPU / Memory / Network / Disk
```

# 3. Why Does Python Exist?

Before languages like Python became popular, developers frequently faced problems such as:

* Complex syntax
* Long development cycles
* Difficult scripting
* Low-level memory management
* Poor readability
* Limited reusable libraries
* Difficulty integrating different systems

Python addresses many of these through:

* Simple syntax
* High-level abstractions
* Automatic memory management
* Extensive standard library
* Huge third-party ecosystem
* Rapid development
* Cross-platform support
* Strong interoperability

### Example

A simple program:

```python
print("Hello, World!")
```

The programmer does not need to manually:

* Allocate memory
* Create a process
* Manage CPU registers
* Handle machine instructions
* Free memory manually

Python provides abstractions over these operations.

# 6. Important Characteristics of Python

Python is commonly described as:

### High-level

You work with abstractions such as:

```python
users = ["Alice", "Bob", "Charlie"]
```

rather than manually managing memory addresses.

### Dynamically typed

You don't normally declare a variable's type explicitly:

```python
x = 10
x = "hello"
x = [1, 2, 3]
```

The name `x` can refer to objects of different types during execution.

### Strongly typed

Python does not silently treat unrelated types as interchangeable in many operations.

For example:

```python
age = 25
name = "Alice"

print(age + name)
```

results in a `TypeError`.

### Interpreted/runtime-executed

Python programs are executed by a Python implementation/runtime.

The simplified model is:

```text
.py source
   ↓
Parser
   ↓
AST
   ↓
Bytecode
   ↓
Python Runtime
   ↓
Machine-level execution
```

Calling Python simply "an interpreted language" is useful for beginners but technically incomplete. Modern Python implementations involve parsing, compilation to bytecode, and runtime execution.

### Garbage collected

Python automatically manages much of object memory.

### Multi-paradigm

Python supports:

```text
Procedural
    +
Object-Oriented
    +
Functional
    +
Async/Event-driven
```

# 9. Python 2 vs Python 3

Python 3 introduced deliberate language improvements that were not completely backward compatible with Python 2.

## Major differences

| Feature          | Python 2                               | Python 3                |
| ---------------- | -------------------------------------- | ----------------------- |
| `print`          | Statement                              | Function                |
| String model     | More complicated text/byte distinction | Unicode text by default |
| Integer division | `5 / 2` → `2`                          | `5 / 2` → `2.5`         |
| `range()`        | Creates list-like sequence             | Lazy sequence object    |
| Exception syntax | Older syntax supported                 | Modern `as` syntax      |
| Type annotations | Not native                             | Supported               |
| F-strings        | No                                     | Yes                     |
| Modern ecosystem | Legacy                                 | Current                 |

Example:

### Python 2

```python
print "Hello"
```

### Python 3

```python
print("Hello")
```

Python 2 reached **end-of-life in 2020**.

For modern development:

> **Use Python 3.**

# 11. CPython

## Definition

**CPython is the reference implementation of Python and is implemented primarily in C.**

When people install Python from the official Python distribution, they are generally using CPython.

Architecture:

```text
Python Program
      │
      ▼
   CPython
      │
      ├── Parser
      │
      ├── Compiler
      │
      ├── Bytecode
      │
      └── Python Runtime
              │
              ▼
         Operating System
              │
              ▼
             CPU
```

## Why CPython matters

CPython provides:

* The standard Python runtime
* C extension support
* Garbage collection mechanisms
* Standard library implementation
* Python object model
* Interpreter execution

A huge portion of the Python ecosystem assumes CPython compatibility.

# 20. Virtual Environments

A virtual environment isolates project dependencies.

Without isolation:

```text
System Python
     │
     ├── Project A → requests 2.x
     │
     ├── Project B → requests 3.x
     │
     └── Project C → conflicting dependencies
```

With virtual environments:

```text
Python Installation
       │
       ├───────────────┐
       │               │
       ▼               ▼
   Project A        Project B
      │                │
      ▼                ▼
    venv A           venv B
      │                │
      ▼                ▼

```

```bash

```

```powershell

```

On Linux/macOS:

```bash
source .venv/bin/activate
```

## What is a PEP?

**PEP stands for Python Enhancement Proposal.**

A PEP is a design document proposing changes or documenting important aspects of Python.

PEPs can describe:

* Language features
* Standards
* Processes
* Governance
* Documentation
* Compatibility changes

# 22. Important PEPs

## PEP 8

Defines the major Python **style guidelines**.

Example:

```python
def calculate_total(price, tax):
    return price + tax
```

rather than poorly formatted code.

---

## PEP 20 — The Zen of Python

Contains guiding principles for Python design.

You can view it with:

```python
import this
```

---

## PEP 257

Defines conventions for docstrings.

---

## PEP 484

Introduced the foundation for Python type hints.

Example:

```python
def add(a: int, b: int) -> int:
    return a + b
```

---

## PEP 585

Allowed built-in collection types to be used directly for type annotations.

Example:

```python
numbers: list[int]
```

---

## PEP 634

Introduced structural pattern matching.

Example:

```python
match command:
    case "start":
        print("Starting")
    case "stop":
        print("Stopping")
```


---

# 24. The Zen of Python — Engineering Interpretation

### "Explicit is better than implicit"

Prefer code whose behavior is easy to understand.

Instead of hiding important behavior:

```python
process(data)
```

you may prefer a design where important dependencies and behavior are clear.

---

### "Simple is better than complex"

If a straightforward solution works:

```python
total = price + tax
```

don't introduce unnecessary architecture.

---

### "Readability counts"

Code is read far more often than it is written.

Therefore:

```python
customer_total = calculate_customer_total(order)
```

is usually preferable to cryptic expressions.

---

### "There should be one obvious way to do it"

Python tends to encourage consistent idioms.

This makes collaboration easier.

# 28. AST — Abstract Syntax Tree

Python can represent program structure using an AST.

Example:

```python
x = 10
```

Conceptually:

```text
       Assign
       /    \
   Name(x)  Constant(10)
```

You can inspect ASTs:

```python
import ast

source = "x = 10"

tree = ast.parse(source)

print(ast.dump(tree, indent=2))
```

This is useful for:

* Static analysis
* Linters
* Code transformation
* Refactoring tools
* Security analysis
* Code generation

# 29. Compilation to Bytecode

Python implementations such as CPython compile source into an intermediate representation called **bytecode**.

Conceptually:

```text
Python Source
      ↓
    Parser
      ↓
     AST
      ↓
   Compiler
      ↓
 Python Bytecode
```

You can inspect CPython bytecode using:

```python
import dis

def add(a, b):
    return a + b

dis.dis(add)
```

The exact bytecode instructions vary between Python versions.

---

# 30. What Is Bytecode?

Bytecode is an intermediate instruction representation used by the Python runtime.

It is **not the same as CPU machine code**.

Think of it as:

```text
Human language
     ↓
Python source
     ↓
Python bytecode
     ↓
Runtime execution
     ↓
Machine-level operations
```

This distinction is extremely important in interviews.

### Interview question

> Does Python compile or interpret code?

Best answer:

> Python implementations vary, but CPython parses and compiles Python source into bytecode and then executes that bytecode using its runtime/interpreter. Therefore, describing Python simply as "interpreted" is an oversimplification.

# 33. Names vs Objects

This distinction becomes critical at advanced levels.

Consider:

```python
x = 10
```

It is better to think:

```text
      x
      │
      ▼
   ┌──────┐
   │  10  │
   │object│
   └──────┘
```

`x` is a **name/reference**, not a box containing the integer in the simplistic C-style sense.

Another example:

```python
x = [1, 2, 3]
y = x
```

Conceptually:

```text
       x ──────┐
               │
               ▼
          ┌─────────┐
          │ [1,2,3] │
          └─────────┘
               ▲
               │
       y ──────┘
```

Both names refer to the same list object.

# 39. `__name__ == "__main__"`

A common Python pattern:

```python
def main():
    print("Application started")


if __name__ == "__main__":
    main()
```

When executing:

```bash
python app.py
```

Python sets:

```python
__name__ == "__main__"
```

When the module is imported:

```python
import app
```

the condition is normally false because the module's name is `app`.

This allows the same file to function as both:

* An importable module
* An executable script

# 60. Interview Preparation

## Beginner Q1: What is Python?

**Answer:**

Python is a high-level, general-purpose programming language known for readable syntax, dynamic typing, automatic memory management, extensive standard libraries, and a large third-party ecosystem.

---

## Q2: Is Python compiled or interpreted?

**Strong answer:**

Python implementations differ. In CPython, source code is parsed and compiled into bytecode, which is then executed by the Python runtime. Therefore, saying Python is simply "interpreted" is an oversimplification.

---

## Q3: What is CPython?

**Answer:**

CPython is the reference implementation of Python and is primarily implemented in C. It is the default implementation used by most Python installations and supports the largest portion of the Python ecosystem.

---

## Q4: What is PyPy?

**Answer:**

PyPy is an alternative Python implementation that includes a JIT compiler and can provide significant performance improvements for certain workloads.

---

## Q5: What is PEP 8?

**Answer:**

PEP 8 is the primary style guide for Python code. It defines conventions for formatting, naming, indentation, imports, and code organization.

---

# 61. Intermediate Interview Questions

## Q6: What is bytecode?

**Answer:**

Bytecode is an intermediate instruction representation produced by implementations such as CPython after compilation of Python source. The Python runtime executes these instructions.

---

## Q7: What is the difference between Python and CPython?

```text
Python
  │
  └── Language specification/ecosystem

CPython
  │
  └── One implementation of Python
```

This distinction is important because Python can have multiple implementations.

---

## Q8: Why does Python use virtual environments?

**Answer:**

Virtual environments isolate project dependencies, allowing different applications to use different package versions without interfering with each other.

---

# 62. Advanced Interview Questions

## Q9: Explain the CPython execution pipeline.

Strong answer:

```text
Source Code
    ↓
Tokenization / Parsing
    ↓
AST
    ↓
Compilation
    ↓
Bytecode
    ↓
CPython Runtime
    ↓
Object execution
    ↓
OS / Hardware
```

The precise implementation details vary by CPython version.

---

## Q10: Is `.pyc` machine code?

**No.**

It contains Python bytecode associated with a Python implementation such as CPython.

```text
.py
 ↓
Python source
 ↓
Bytecode
 ↓
Python runtime
```

It is not equivalent to:

```text
C source
 ↓
native compiler
 ↓
CPU machine code
```
